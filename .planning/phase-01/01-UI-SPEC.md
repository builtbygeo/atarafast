## Visual Design Contract

### Spacing Scale

Declared values (8-point scale, multiples of 4). Inherited from Tailwind CSS 4 defaults. All existing project values are preserved.

| Token | Value | Usage in This Phase |
|-------|-------|---------------------|
| 1 (xs) | 4px | Tab icon-to-label gap, section micro-spacing |
| 2 (sm) | 8px | Tab bar horizontal padding (px-2), compact element gaps |
| 4 (md) | 16px | Tab bar horizontal padding on wider screens (px-4), component padding |
| 6 (lg) | 24px | Tab bar top padding (pt-6 → pt-6 preserved), header spacing |
| 8 (xl) | 32px | Inter-section gaps |
| 12 (2xl) | 48px | Explicit minimum tap target height: `min-h-[48px]` |
| 16 (3xl) | 64px | Explicit minimum tap target width: `min-w-[64px]` |

**Phase-specific overrides:**
- Tab bar vertical padding: `pt-2.5` (10px, top) + `pb-[max(0.75rem,env(safe-area-inset-bottom))]` (bottom) — 10px top padding provides visual breathing room for the dot indicator
- Tab button internal padding: `py-1.5` (6px) + `gap-1` (4px icon-to-label)
- No other exceptions to the 8-point scale

### Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Tab label | 11px (`text-[11px]`) | 600 (`font-semibold`) | 1 | Bottom nav tab labels (EN/BG) |
| Tab label tracking | — | — | `tracking-wide` (0.025em) | Subtle spacing for readability — REPLACES current `tracking-widest` |
| Button press state | 11px | 600 | 1 | Same size, transforms on press |
| Heading (premium banner) | 14px (`text-sm`) | 900 (`font-black`) | 1.25 | Premium banner heading — KEEP as-is |
| Body (premium banner) | 11px (`text-[11px]`) | 500 (`font-medium`) | 1.5 (`leading-relaxed`) | Premium banner description — KEEP as-is |

**Critical change from current state:**
- Tab label weight: `font-black uppercase tracking-widest` → `font-semibold tracking-wide` (no uppercase). Black + uppercase + widest tracking is harsh for a wellness app. Semibold + wide tracking is elegant and more readable at 11px.
- Tab label size: `text-[9px] sm:text-[10px]` → `text-[11px]` (consistent). 9px fails WCAG minimum readable size at common zoom levels.

**Font family:** `var(--font-inter), 'Inter', system-ui, sans-serif` — already configured in `globals.css:79`. No change.

## Component Contracts

### Tab Bar Component

**Element:** `<nav>` with `<button>` children (NOT `<a>` links, NOT Radix Tabs). This is app-level navigation, not inline tab content.

#### Dimensions

| Property | Value | Rationale |
|----------|-------|-----------|
| Position | `fixed bottom-0 inset-x-0` | Persistent bottom nav — never hide on scroll |
| Max width | `max-w-md mx-auto` | Constrain to mobile viewport width; centered on tablet+ |
| Height | Content-driven (~68px from padding + content) | Not fixed-height; responds to content + safe area |
| Top padding | `pt-2.5` (10px) | Visual breathing room above icons, space for indicator dot |
| Bottom padding | `pb-[max(0.75rem,env(safe-area-inset-bottom))]` | 12px or more for safe area on notched devices |
| Horizontal padding | `px-2` (8px) mobile → `px-4` (16px) sm+ | Tighter on small screens, balanced on larger |
| Grid | `flex items-center justify-around` | Equal spacing for 3 tabs; `justify-around` distributes evenly |
| Z-index | `z-50` | Above all content, below dialogs/sheets |

#### Tab Button (individual)

| Property | Value |
|----------|-------|
| Layout | `flex flex-col items-center gap-1` (4px icon-to-label gap) |
| Min tap target | `min-w-[64px] min-h-[48px]` — WCAG 2.1 SC 2.5.5 compliant |
| Internal padding | `py-1.5` (6px vertical) — provides internal space without adding height |
| Icon size | `h-6 w-6` (24×24px) — KEEP existing lucide icon size |
| Label size | `text-[11px]` — UP FROM current 9px |
| Label weight | `font-semibold` — DOWN FROM current font-black |
| Label tracking | `tracking-wide` (0.025em) — SOFTER THAN current tracking-widest |
| Label casing | Normal case (REMOVE `uppercase`) |
| Press feedback | `active:scale-95` — SOFTER THAN current active:scale-90 (5% shrink vs 10%) |
| Transition | `transition-all duration-200` — KEEP existing timing |
| Focus ring | `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2` — ADD (currently missing) |
| ARIA | `aria-label={label}`, `aria-current={activeTab === id ? "page" : undefined}` — KEEP aria-label, ADD aria-current |
| Role | `<button>` inside `<nav>` — correct semantic pattern for navigation. Do NOT add `role="tablist"`/`role="tab"` |

#### Tab Button States

| State | Visual |
|-------|--------|
| **Active** | `text-primary` (green accent) for icon + label. Dot indicator animated via `layoutId`. Background: none (transparent — the pill indicator is the dot, not a background fill). |
| **Inactive** | `text-muted-foreground/50` (grey at 50% opacity). No dot. |
| **Inactive-hover** | `hover:text-foreground` (white, full opacity). `hover:bg-white/[0.03]` (subtle 3% white pill). `rounded-2xl` on hover background. |
| **Press** | `active:scale-95` (5% shrink over 200ms transition). Applies to all tab buttons. |
| **Focus-visible** | `focus-visible:ring-2 focus-visible:ring-ring` ring offset by 2px. Keyboard-navigable tab order. |

#### Active Indicator Dot

| Property | Value |
|----------|-------|
| Position | `absolute -top-1 left-1/2 -translate-x-1/2` — centered above the tab content, 4px above |
| Size | `h-1 w-1` (4×4px) |
| Shape | `rounded-full` (circle) |
| Color | `bg-primary` (accent green) |
| Animation | framer-motion `layoutId="tab-indicator"` with `transition={{ type: "spring", stiffness: 500, damping: 30 }}` |
| Reduced motion | When `prefers-reduced-motion: reduce` is active, skip `layoutId` (no spring animation). Show dot instantly on active tab. |

**Why a 4px dot, not a pill background?** RESEARCH.md documented that a dot indicator is unambiguous for colorblind users (shape + position = two cues), while color-only active states fail accessibility. The small dot also preserves the minimal aesthetic — no chunky pill backgrounds competing with the timer's circular progress.

## Premium Gate Visibility

### When `ENABLE_PREMIUM=false` (Current Production State)

The following premium-related UI elements MUST be hidden:

| Element | Location | How It's Hidden |
|---------|----------|-----------------|
| 30-day history filter | `page.tsx:86-91` (`displayHistory` useMemo) | Guard: `if (!ENABLE_PREMIUM) return history` — skip filter entirely, return full history |
| "Unlock full history" banner | `history-view.tsx:232-249` | Guard: `{ENABLE_PREMIUM && hasHiddenRecords && (` — banner only renders when premium is enabled AND there are hidden records AND user is not premium |
| "Upgrade to Atara" button | Inside the banner above | Hidden with the banner — code preserved in file |
| `hasHiddenRecords` calculation | `page.tsx:93-96` | Guard: `if (!ENABLE_PREMIUM) return false` — no "hidden records" concept when premium is off |
| `startCheckout()` call from banner | `history-view.tsx:244` | Hidden with the banner |

**Guard pattern to follow everywhere:**
```tsx
import { ENABLE_PREMIUM } from '@/lib/features'

// Data level: bypass filter when premium is disabled
const displayHistory = useMemo(() => {
  if (!ENABLE_PREMIUM) return history  // ← ADD this line
  if (isPremium) return history
  const thirtyDaysAgo = new Date()
  thirtyDaysAgo.setDate(thirtyDaysAgo.getDate() - 30)
  return history.filter(r => new Date(r.startTime) >= thirtyDaysAgo)
}, [history, isPremium])

// UI level: hide banner when premium is disabled
const hasHiddenRecords = useMemo(() => {
  if (!ENABLE_PREMIUM) return false  // ← ADD this line
  if (isPremium) return false
  return displayHistory.length < history.length
}, [history, displayHistory, isPremium])
```

**What stays visible:**
- All premium-gated features wrapped in `<PremiumGate>` component — the component already checks `ENABLE_PREMIUM` at line 21 of `premium-gate.tsx` and returns children when disabled. No change needed for existing PremiumGate usages.
- The `UpgradeDialog` component — it remains wired but its triggers (buttons calling `setUpgradeOpen(true)`) must be guarded by `ENABLE_PREMIUM` checks.

## Animation & Transitions

### Tab Switching (Content Area)

| Property | Value |
|----------|-------|
| Method | CSS `transition-opacity duration-150` (NOT framer-motion AnimatePresence) |
| Duration | 150ms |
| Easing | Default ease (CSS `ease`) — linear-enough for a fast opacity fade |
| Visual | Opacity crossfade: active view fades in (0 → 1), inactive fades out (1 → 0) |
| Direction | None — no horizontal slide, no vertical shift. Pure crossfade only. |
| Exit animation | NOT used — all views stay mounted. Exit animations would unmount components, killing timer state. |

**Why CSS opacity, not framer-motion for content transitions:**
- RESEARCH.md recommends opacity toggling for state preservation (all three views mounted simultaneously)
- framer-motion `AnimatePresence` with `mode="wait"` would exit-unmount views, destroying timer state
- CSS opacity achieves the visual polish (crossfade) without the technical cost (state loss)
- Deferred to v2: full framer-motion tab transitions (NAV-03)

### Tab Indicator Dot Animation

| Property | Value |
|----------|-------|
| Method | framer-motion `layoutId="tab-indicator"` — shared element animation |
| Spring config | `stiffness: 500, damping: 30` — snappy, no bounce |
| Visual | 4×4px circle slides along the tab bar to the active tab position |
| Reduced motion | Skip `layoutId` when `prefers-reduced-motion: reduce` — show dot instantly on active tab (no animation) |
| Cost | GPU-composited (CSS transform). No layout thrashing. |

**Implementation note:** The `layoutId` goes on the active indicator dot, which only renders for the active tab. framer-motion tracks the `layoutId` across instances and animates the position change. This is a standard framer-motion pattern — works with conditional rendering of the dot.

```tsx
{activeTab === id && (
  <motion.div
    layoutId={prefersReducedMotion ? undefined : "tab-indicator"}
    className="absolute -top-1 left-1/2 -translate-x-1/2 h-1 w-1 rounded-full bg-primary"
    transition={prefersReducedMotion ? { duration: 0 } : { type: "spring", stiffness: 500, damping: 30 }}
  />
)}
```

### Reduced Motion Hook

No existing hook for `prefers-reduced-motion`. Add inline check in page.tsx (single file, no new hook file needed for this pattern):

```tsx
// Inside the Home component:
const [prefersReducedMotion, setPrefersReducedMotion] = useState(false)

useEffect(() => {
  if (typeof window === "undefined") return
  const mql = window.matchMedia("(prefers-reduced-motion: reduce)")
  setPrefersReducedMotion(mql.matches)
  const handler = (e: MediaQueryListEvent) => setPrefersReducedMotion(e.matches)
  mql.addEventListener("change", handler)
  return () => mql.removeEventListener("change", handler)
}, [])
```

### Touch Targets

| Element | Size | WCAG 2.1 SC 2.5.5 |
|---------|------|--------------------|
| Tab button | `min-w-[64px] min-h-[48px]` | ✓ PASS (exceeds 44×44px minimum) |

All touch targets exceed the 44×44px WCAG minimum. Even on the tightest screens (320px wide), three tabs at 64px minimum width = 192px, leaving 128px for padding and gaps — comfortable with `justify-around`.

### Thumb Zone

The tab bar sits at the very bottom of the screen (fixed bottom-0), within the natural thumb reach arc for both right-handed and left-handed users on mobile. The 3-tab layout (vs current 4) provides 33% wider tap targets, reducing mis-taps — particularly important for the center tab (Log).

### Viewport Constraints

| Property | Value | Rationale |
|----------|-------|-----------|
| Max width | `max-w-md` (448px) | Mobile app feel on tablet — content doesn't stretch edge-to-edge |
| Min width | 320px (iPhone SE 1st gen) | All content must fit and function at 320px viewport |
| Height | `h-dvh` (dynamic viewport height) | Accounts for mobile browser chrome (URL bar) without overflow |
| Overflow | `overflow-hidden` on main | Prevents body scroll; each view handles its own scrolling internally |
| Overscroll | `overscroll-none` on main | Prevents pull-to-refresh and rubber-banding on iOS |

### Keyboard / Desktop

This is a mobile-first PWA. Desktop users (if any) see the `max-w-md` constrained viewport centered on screen. Tab navigation works identically with keyboard Tab key + Enter/Space. Focus-visible rings added to tab buttons for keyboard users.

| Default | `"today"` (no stored value, corrupt value, or first visit) |
| On switch | `localStorage.setItem("atara-active-tab", tab)` on every tab change |
| On load | `useState<Tab>(() => localStorage.getItem("atara-active-tab") as Tab \|\| "today")` |
| PWA cold start | User returns to last-used tab, not always Today |

### Timer State Across Tab Switches

| Concern | Solution |
|---------|----------|
| Timer interval continues | All three views mounted simultaneously (CSS visibility toggle, not conditional render) |
| Fast state preserved | `getActiveFast()` reads from localStorage on mount — but mount only happens once (views stay mounted) |
| Timer accuracy | `setInterval` in TimerView continues running when view is `opacity-0 z-0` — no interruption |
| Hidden view events | `pointer-events-none` on hidden views prevents accidental interactions |
